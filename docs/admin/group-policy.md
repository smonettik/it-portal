# Групповые политики (GPO)

Групповые политики — механизм централизованной настройки компьютеров и пользователей в домене Active Directory. Один объект политики может сразу настроить сотни параметров на всех компьютерах подразделения: от установки принтеров до запретов в целях безопасности.

## Основные понятия

- **GPO (Group Policy Object)** — объект групповой политики, набор настроек;
- **OU (Organizational Unit)** — подразделение, контейнер в Active Directory, к которому привязывается политика;
- **Домен** — вся сеть компании под управлением Active Directory.

!!! info "Где работать"
    Политики редактируются с контроллера домена или с компьютера администратора с установленным RSAT: Пуск → **Group Policy Management** или команда `gpmc.msc`.

## Создание политики для подразделения

1. Открой **Group Policy Management**.
2. Раскрой домен и найди нужное OU (например, компьютеры «Энергия-5»).
3. Правой кнопкой по OU → **Create a GPO in this domain, and Link it here**.
4. Дай понятное имя, например `Energy-5_Security`.
5. Правой кнопкой по созданной политике → **Edit** — откроется редактор настроек.

## Типовые политики, применяемые в компании

### Запрет редактирования реестра

Путь: User Configuration → Policies → Administrative Templates → System.
Политика: **Don't run Windows Registry editing tools** → Enabled.

### Настройка автоматического обновления Windows

Путь: Computer Configuration → Policies → Administrative Templates → Windows Components → Windows Update.
Здесь задаётся расписание установки обновлений и поведение перезагрузки.

### Подключение сетевых дисков

Путь: User Configuration → Preferences → Windows Settings → Drive Maps.
Диск подключается по сетевому пути, например `\\server\share`.

### Установка принтеров по IP

Путь: Computer Configuration → Preferences → Control Panel Settings → Printers.
Принтер добавляется по TCP/IP-порту — так подразделения получают нужный принтер без ручной установки.

### Скрипты при входе в систему

Путь: User Configuration → Policies → Windows Settings → Scripts (Logon/Logoff).
Используется для запуска служебных скриптов при входе пользователя.

## Обновление политик на компьютерах

На клиентском компьютере выполни:

    gpupdate /force

Проверка применившихся политик:

    gpresult /r

## Устранение неполадок

1. **Политика не применяется** — проверь, что GPO привязана к нужному OU и компьютер входит в это OU; выполни `gpresult /r` на клиенте.
2. **Конфликт политик** — по умолчанию приоритет у политики, привязанной ближе к объекту; режим **Enforced** используй только осознанно.
3. **Политика применялась к тесту, но не к остальным** — проверь Security Filtering: по умолчанию политика применяется к Authenticated Users.

!!! warning "Важно"
    - Не изменяй **Default Domain Policy** — создавай отдельные GPO под каждую задачу;
    - Сначала тестируй политику на тестовой группе компьютеров;
    - Называй GPO по схеме «подразделение_назначение», например `Energy-8_Printers`.
